# Khaos M8.6 — Coding UX / Supervision / Checkpoint / Rewind Closure Report

当前 verdict：`NOT_CLOSED`（实现、focused regression 与本地 product gate 已完成；
本报告仍等待推送后的 exact-SHA required CI terminal evidence）。

## 1. Executive Summary

M8.6 adds an owner-scoped typed Coding supervision plane, cooperative task control,
bounded immutable checkpoints, and generation-bound rewind through the existing
M8.2 `EditTransaction` path. Presentation adapters are projections only. No new
Git reset/clean path, completion authority, verification authority, or permission
authority was introduced.

## 2. Pre-M8.6 UX Architecture

Before M8.6, TurnCoordinator, TaskManager, WorkspaceManager, M8.2 edit
transactions, M8.3 verification, and M8.5 child/merge records were durable but
there was no single restart-safe user-facing Coding projection. M8.6 joins those
existing owners at the application boundary rather than creating a second state
machine.

## 3. Supervision Event Model

`SupervisionEvent` has a typed event vocabulary, owner binding, per-task sequence,
canonical digest, bounded payload, actor and severity. Payload validation rejects
source/content, diff/patch, stdout/stderr, output, transcript, prompt and similar
fields. The event table is append-only through SQLite triggers.

## 4. Supervision Projection

`TaskSupervisionState` is a bounded projection containing status, current activity,
plan, changed paths, verification/approval/merge state, active subagents,
checkpoint references, blockers, known file digests and completion eligibility.
Projection updates are derived by `TaskSupervisionRepository`; state digest and
owner/project binding are verified on read.

## 5. User-Facing Task States

The typed state set covers `PLANNING`, `INVESTIGATING`, `EDITING`, `VERIFYING`,
`REPAIRING`, `WAITING_FOR_APPROVAL`, `RUNNING_SUBAGENTS`, `INTEGRATING`,
`PAUSED`, `BLOCKED`, `READY`, `COMPLETED`, `FAILED`, `CANCELLED`,
`QUARANTINED`, plus internal `PAUSING`.

## 6. Plan/Activity UX

AgentLoop projects plan creation, context preparation and tool-step activity.
Activity contains operation/kind/stage/description, bounded scope and status.
The TUI, CLI and Gateway consume the projection; they do not calculate an
independent repository diff or infer completion from text.

## 7. Edit UX

M8.2 remains the sole file mutation owner. A Coding edit batch is admitted only
after a pre-edit checkpoint is captured. Successful typed edit results update
known file digests and emit bounded `edit.applied` facts containing transaction
identifiers/digests and relative paths, not source text.

## 8. Verification UX

The existing M8.3 coordinator/ledger remains authoritative. M8.6 projects
`verification.started`, `verification.passed`/`verification.failed`, and repair
activity, while verification output stays outside supervision payloads. A
verification progress or model summary cannot make `completion_eligibility`
positive.

## 9. Subagent/Merge UX

M8.5 `SubagentCoordinator` now projects typed child started/finished state with
active assignment IDs and bounded result/verification digests. `MergeCoordinator`
continues to own the merge plan, resource barrier, publication and post-merge
checkpoint hooks. Child and merge events never grant completion authority.

## 10. Approval UX

AgentLoop emits `approval.requested` with operation identity, binding digest and
expiry, and records the workspace binding. TaskService emits
`approval.resolved` only after the existing ApprovalBroker commit path succeeds.
The projection exposes pending/approved/rejected state without approval secrets.

## 11. Task Control Service

`TaskControlService` owns durable task-scoped control state and in-memory runtime
wake-up handles. Commands bind task/workspace/principal/project, expected revision
and command ID. Results are typed and idempotent: `APPLIED`, `NOOP`,
`REJECTED_STALE`, `BLOCKED`, `REQUIRES_APPROVAL`, or `FAILED`.

## 12. Pause Semantics

Pause persists `PAUSING` before asking the active runtime to stop at a safe point.
The AgentLoop checks control before each model turn, after a model stream and
before tool admission. It does not admit new model/tool/child effects while
paused; in-flight critical effects remain owned by their existing effect owner.

## 13. Resume Semantics

Resume is accepted only from durable `PAUSED`, sets the runtime context-rebuild
flag, wakes the safe-point waiter and causes the next context to be rebuilt. A
stale expected revision is rejected. Restart registration re-reads the durable
control state rather than assuming the old in-memory state survived.

## 14. Cancel Semantics

Cancel enters `CANCELLING` for an active runtime and requests cooperative task
cancellation. AgentLoop settles existing task/lease truth and emits the terminal
cancel fact; no rewind is performed. Inactive tasks can transition directly to
durable `CANCELLED`. Existing child/workspace cleanup ownership is preserved.

## 15. Checkpoint Contract

`TaskCheckpoint` binds task/workspace/principal/project, repository generation,
HEAD/tree, task/plan revision, verification evidence, kind/label and a bounded
snapshot digest. Snapshot files are read through the WorkspaceManager storage
scope and `SafeWorkspaceFS`; path, entry, depth, file and byte bounds apply.

## 16. Automatic Checkpoint Policy

The implemented automatic kinds are `PRE_EDIT`, `POST_VERIFICATION`,
`PRE_PARALLEL_MERGE` and `POST_MERGE`. Capture is required before Coding mutation,
created after a successful verified edit, and integrated into the existing M8.5
merge owner. Duplicate identity requests are idempotent and task quotas are
bounded.

## 17. Checkpoint Persistence

Migration v30 adds `task_checkpoints` with owner indexes and immutable update/delete
triggers. Checkpoint creation is stable-state checked and records bounded audit
metadata plus a canonical supervision event. The snapshot is never silently
rebound to a different owner or workspace.

## 18. RewindPlan

`RewindPlan` contains source generation/HEAD/tree/snapshot digest, target checkpoint
identity, affected/preserved/user-drift/conflict paths, a fresh M8.2 transaction,
transaction digest and expected resulting generation. Plan digest covers all of
these fields, including the uncommitted snapshot binding.

## 19. Rewind Execution

Execution re-reads the owner-scoped checkpoint and current workspace, rejects
barriers or stale identity, applies only the planned `EditTransaction`, records
the resulting edit projection, and persists a typed result. It never invokes
`git reset --hard` or `git clean`.

## 20. Generation Semantics

A successful rewind requires the current generation/HEAD/tree/snapshot to match
the plan and produces the M8.2 service's next generation (`N -> N+1`). Old
verification evidence is not re-used as proof for the new generation. Concurrent
terminal result writes use a result-null CAS and return the durable winner.

## 21. User Drift Preservation

Known model-owned files with user drift are reported as conflicts. New/unowned
files are preserved by default; if the target would overwrite an unowned path,
the plan is blocked. The candidate affected set remains visible even when the
plan has no executable transaction.

## 22. Verification After Rewind

After a mutation, the existing M8.3 verification coordinator is invalidated and,
when configured, run again against the new edit result. The result is marked
`APPLIED` only when fresh verification passes; effect-applied but failed or
unavailable verification remains a failed/unverified truthful result.

## 23. Subagent/Merge Barriers

Rewind planning and execution check active runtime/control, active child or merge
records, active subagents, pending approvals, merge state and workspace capture
reservations. M8.5 pre/post merge checkpoint and publication barriers remain
owned by MergeCoordinator and are not bypassed by the UX layer.

## 24. Restart/Recovery

Events, projection, control state, checkpoints and rewind records survive service
object recreation. Runtime registration rebinds the exact owner and checkpoint
service. A persisted rewind result is returned on retry; an incomplete physical
effect is never inferred as successful merely because a process restarted.

## 25. API/CLI/TUI Integration

Python TaskService exposes supervision snapshot/replay, pause/resume/cancel,
checkpoint list/show/create and rewind plan/execute. Go adds an optional typed
`TaskControlClient` surface while preserving the legacy `TaskClient` interface.
CLI adds `task`, `checkpoint` and `rewind` commands. TUI adds status/control and
checkpoint/rewind preview commands; TUI does not execute a rewind directly.

## 26. Security Adversarial Matrix

Covered controls include owner/project mismatch, stale command revision, command
idempotency, source/output event rejection, digest tamper, replay sequence gap,
workspace owner mismatch, stale uncommitted drift, unowned-file preservation,
active-runtime blocking, active-child/merge barriers and no-false-green
verification projection. Authorization, sandbox, network, credential, Trusted
Git, M8.2, M8.3 and CompletionGate remain existing authorities.

## 27. Long-Horizon/Performance

Event history is bounded per replay request, state payloads and paths are bounded,
checkpoint count/files/bytes/operations are bounded, and control locks are
per-task owner keys rather than a global lock. A production long-session load
benchmark and operational latency threshold are not yet recorded in this report.

## 28. M8.0 Regression

The existing M8.0/M8.5 focused suites remain in the validation set. M8.6 changes
are adapter/projection additions around existing owners; no completion, approval,
workspace, edit or verification bypass was introduced. The combined M8.6/M8.5/
TUI/CLI local regression passed `63 passed`, and the selected full Python product
suite passed `5414 passed, 9 skipped, 65 deselected`.

## 29. Static/Language Regression

Focused Python `compileall` and Ruff checks pass after the latest implementation

## 31. Known Limitations

The TUI intentionally previews rewind rather than executing it. Checkpoint and
rewind control through TaskService requires the active canonical workspace owner;
an unavailable owner returns `BLOCKED`. A full production AgentLoop pause/cancel
timeline, restart drill, long-session benchmark and every CI matrix profile are
not claimed by this local report. The SafeWorkspaceFS-backed checkpoint/rewind
fixture tests are explicitly `posix_host`; Windows retains fail-closed coverage
for the unavailable `O_NOFOLLOW`/`dir_fd` boundary rather than receiving a weaker
filesystem fallback.
