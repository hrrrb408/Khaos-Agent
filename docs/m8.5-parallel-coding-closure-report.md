# Khaos M8.5 — Parallel Coding / Subagent Worktrees Closure Report

状态：实现与本地专项验证完成；远端 exact-SHA CI 在推送后记录。本文不把
Child 观察结果提升为 Parent completion，也不替代现有安全与产品门禁。

## 1. Scope

本轮实现 bounded parallel Coding child、独立 Task Worktree、确定性
Integration Worktree merge、Parent CAS publish、重启 unknown 和生命周期审计。

## 2. Baseline

继续使用当前 `codex/m8-coding-evaluation` 分支和既有 PR #230；没有新建第二个
PR。M8.2 EditTransaction、M8.3 Verification、M8.4 Context、M7.8 delegated
runtime 与 CompletionGate 保持既有 owner。

## 3. Authority Ownership

`SubagentCoordinator` 只编排；WorkspaceManager/TrustedGit 管 Worktree 与 Git；
EditTransaction 管 Child edit；M8.3 管 verification；Repo Intelligence 只在
发布后 refresh；CompletionGate 仍是唯一完成 authority。

## 4. Assignment Contract

`SubagentAssignment` 是 frozen、digest-bound、depth=1 的类型化输入，绑定
Parent task/workspace/principal/project、base generation/commit、role、scope、
tools、policy 与 child principal。

## 5. Context Transfer

Child 只收到 bounded objective、constraints、instructions、selected paths/
symbols、diagnostics 和 decisions。ContextTransferPackage 有 item/byte 上限，
不携带 Parent transcript 或无界 memory。

## 6. Parent Stability

创建 Child 和规划 merge 前均复核 Workspace state、worktree identity、干净 raw
diff、generation 与 Git HEAD；dirty 或 in-flight ChangeSet 会拒绝 admission。

## 7. Child Worktree Isolation

每个 assignment 通过现有 WorkspaceManager 创建独立 Git Worktree 和 branch；
Child path 与 Parent/sibling 不复用。失败、取消和非成功结果走现有强制 cleanup。

## 8. Child Principal

Child principal 固定为 `subagent:<parent-principal>:<assignment-id>`，child
runtime/project 也进入 binding。Role 本身不授予 authority；Research/Review
强制 read-only。

## 9. EditTransaction Binding

Child 通过现有 EditTransactionService 和 WorkspaceStorageAuthority 进行写入，
继续受 generation、路径、symlink、storage、rollback 和 audit 边界约束。

## 10. Generation/CAS

Child generation 与 Parent 独立；Parent generation 只在受控 publish commit
后推进。MergePlan 绑定 Parent base HEAD/generation，旧 candidate 在 Parent 漂移
后返回 `REJECTED_STALE`。

## 11. Scheduler and Budgets

BoundedParallelScheduler 限制 active/mutating/research child 数量、turn/token/
tool/storage/duration 及 aggregate token/tool budget；容量不足排队，形成安全
serial fallback，不通过放宽限制取得并发。

## 12. Dependency/Overlap Validation

计划校验 missing dependency、cycle、duplicate id 和 overlapping mutating scope；
只实现有界依赖等待，不引入通用 DAG/mesh。

## 13. Child Result Evidence

`SUCCESS` 需要 child final commit、ChangeSet artifact 和 child verification；
结果带 base、artifact digest/length、change digest、changed paths、evidence
digest/ref 与 result digest。Child success 不等于 Parent success。

## 14. Deterministic Merge Plan

MergePlan 按 priority 后 assignment id 排序，绑定 candidate ids、Parent snapshot、
conflict set 和 plan digest。Path/symbol/base/assignment/artifact 冲突 fail closed。

## 15. Integration Worktree

MergeCoordinator 自己拥有临时 Integration Worktree，只按 candidate artifact
应用，不运行模型、不接受自由 edit；Integration identity 绑定 plan digest 与
Parent base。

## 16. Parent Publish

Integration verification 通过后，才在 Parent storage scope 中以 artifact apply、
ChangeSet build、commit-tree/update-ref 和 HEAD/generation CAS 发布。没有
`git reset --hard` 或 canonical Parent `git clean`。

## 17. Post-Merge Verification

Integration 与 resulting Parent 各执行一次既有 M8.3 Verification Planner/
Executor/Evidence 链路；Parent verification 使用新的 merge transaction digest、
resulting commit/generation，Child green 不会被复用为 Parent evidence。

## 18. Repo Intelligence Refresh

Parent publish 且 Parent verification 通过后才调用现有 workspace-bound
RepoIntelligence refresh；refresh 失败不会被包装成 completion success。

## 19. Completion Boundary

M8.5 没有新增 CompletionGate。required assignment、active/quarantined child、
merge conflict 和 verification facts 仍由既有 completion/recovery/control
plane 解释，最终 `COMPLETE` 只能由现有 CompletionGate 投影。

## 20. Cancellation/Cleanup

Scheduler 取消并 drain child worker；Coordinator 对非成功 Child 清理 worktree/
branch/artifacts；Integration cleanup 对 success/conflict/failure/cancel 均执行。
无法证明 terminal cleanup 时保留 `QUARANTINED`。

## 21. Restart Recovery

v29 durable repository 保存 assignment、binding、result、merge plan/result 和
append-only events。重启扫描 RUNNING/MERGING 等未完成记录并标为 `UNKNOWN`，不把
中断状态猜成成功；跨进程 Worktree 回收仍需有权威 manager/operator 重新接管并
证明 cleanup。

## 22. Adversarial Review

已审查 child 写 Parent/sibling、dirty/stale Parent、HEAD/generation race、旧
artifact/replay、path/symbol overlap、symlink/`.git` scope、duplicate publish、
cancel race、cleanup quarantine、quota bypass 和 restart ambiguity。额外加入
artifact 所属 Child 与实际 changed-file 对比，阻止“声明范围内、artifact 超范围”
的伪造结果。

## 23. Local Validation

已通过：M8.5 专项 9 tests、M8.3/M8.5 相关回归、runtime factory 回归、changed-file
ruff、`compileall` 与 migration source-integrity。Trusted Git 测试使用项目现有
CLT Git 环境；默认 `/usr/bin/git` 的 Xcode license gate 是宿主机环境限制，不是
代码断言结果。

## 24. CI Evidence

推送前为 pending。仓库实际 merge authority 是 `Security Closure Gate` 与
`Product Integrity Gate` 两个 aggregate check；两者都必须绑定本次 head SHA、
原始 attempt 1 并终态 success。详细 Linux/macOS/Windows、Go/Rust、Docker、
供应链和 Security Evidence artifact 只采用本次 exact-SHA run，不沿用旧 PR 结果。

## 25. Known Limitations and Release Decision

本轮不实现自动生成完整 Child AgentLoop；由可信 execution adapter 通过
`ChildWorker` 接入既有运行时。Restart recovery 保守地落到 unknown，不能在缺少
新进程 authority 时假装完成 cleanup。基于本地专项与既有 owner 复用，代码可提交
并进入 required CI；只有本报告更新后的 exact-SHA Product Integrity 与 Security
Closure 均成功，才可声明 M8.5 远端闭环；不进入 M8.6。
