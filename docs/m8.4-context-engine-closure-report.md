## 1. Architecture

`ContextEngineService` is the single model-context selection, bounded assembly,
compression, and serialization owner on the normal runtime-factory path. It does
not execute tools, authorize or approve operations, mutate repositories, run
verification, or decide completion.

The authority chain remains separated:

```text
AgentLoop orchestration
  -> M8.1 ContextIntelligenceService: typed repository candidates
  -> M8.4 ContextEngineService: working set, requirements, selection, serialization
  -> M8.2 EditTransaction: canonical edits
  -> M8.3 Verification Planner/Coordinator: verification evidence
  -> existing Permission / Approval / Workspace / Completion authorities
```

## 2. Before M8.4 Context Flow

The old path directly combined the application prompt, the complete persisted
message list, memory, a rendered repository bundle, and raw tool output. Context
compression and tool schema construction were separate paths. This made the
working set, freshness, output bounds, and cache evidence implicit.

The normal path now passes typed inputs through one final selector. The old
`AgentLoop._build_legacy_context()` is an explicit compatibility adapter used only
when a loop is directly constructed without an engine; the runtime factory always
constructs and wires M8.4.

## 3. Four-Layer Working Set

| Layer | Lifecycle | Default token budget | Default byte budget |
| --- | --- | ---: | ---: |
| L0 | persistent system/project rules | 2,048 | 48 KiB |
| L1 | task goal, constraints, plan, decisions, changed files | 3,072 | 64 KiB |
| L2 | current-step regions, symbols, diagnostics, relations | 5,120 | 112 KiB |
| L3 | recent conversation, tool and verification evidence | 1,760 | 32 KiB |

`TaskWorkingSet` is immutable/copy-on-write and bounded to 256 items, 128 file
references, and 64 values per bounded fact collection. Repository source items
persist as references and digests, not large snippets.

## 4. Context Contracts

`ContextItem`, `ContextRequirements`, `ContextSelection`, `ContextMessage`,
`ModelContext`, `TaskStateSummary`, and `ContextMetricsSnapshot` provide typed
contracts. Items carry kind, layer, source, trust, workspace, generation, digest,
region, priority, required/pinned state, and approximate-cost markers.

The deterministic token estimator is explicitly approximate:
`max(word_count, ceil(UTF-8-bytes / 4))`. Provider billing remains owned by the
existing token engine.

## 5. Budget Model

The default context window is 12,000 tokens / 256 KiB with an output reserve of
2,048 tokens / 32 KiB. Therefore normal selection has 9,952 tokens / 224 KiB
available. Layer budgets are independently configurable; the selector preserves
L0 when a caller supplies an impossible budget and evicts lower-priority items
first. Tool envelopes also reject an impossible structural byte bound instead of
returning an oversized result.

Measured overflow case:

```text
total: 70 tokens / 2,048 bytes
reserve: 10 tokens / 256 bytes
available: 60 tokens / 1,792 bytes
layers: (20,20,30,20) tokens / (512,512,768,512) bytes
selected: 15 tokens / 60 bytes
evicted: 39 items
first deterministic eviction: src/old38.py
```

## 6. Retrieval / Selection

M8.1 remains the only repository candidate provider. M8.4 consumes the typed
bundle's documents, symbols, evidence, and `structure_paths`; it does not scan a
repository or create a second semantic index. Candidates are filtered by workspace
and generation before selection, then stably ordered by requirement, target match,
priority, layer, kind, path/region, sequence, digest, and item id.

Exact duplicates are removed. Overlapping file regions merge only when path,
generation, source, and trust all match. The merged item retains the lower-trust
classification and a bounded combined digest.

## 7. Precise Source Regions

M8.1 document excerpts carry relative path, start/end lines, content digest, index
generation, and relevance. Symbols carry qualified name and bounded line range.
The normal M8.4 path sends these typed regions directly to the selector rather than
serializing one unbounded `ContextBundle` message.

## 8. Tool Output Bounding

All normal-path model-visible tool results use `ToolOutputEnvelope` with bounded
status, summary, important fields, content, first/last diagnostic lines,
`truncated`, full-result digest, and approximate output cost. Default limits are
64 KiB, 4,096 estimated tokens, and 512 lines. The raw output metadata field is
cleared on the engine path; the durable digest and truncation state remain.

Measured 4 KiB envelope case: 987 visible bytes, 38 approximate tokens,
`truncated=true`, a 64-hex-character digest, and the final diagnostic retained.

## 9. Tool Discovery

Coding mode exposes the deterministic core set first and defers browser/web/MCP,
remote/channel/cron, Git mutation, clipboard, and subagent specialists until the
intent requests them. Ordinary coding sample: 4 registered tools became 1 visible
tool (`read_file`); a remote/push intent exposes `git_push` as well. Branch and
commit aliases (`git_create_branch`, `git_smart_commit`) are also intent-aware.

Visibility is only a model-schema optimization. Registry membership, allowlists,
Permission, Approval, and scheduler authority are unchanged. Office mode retains
its existing registered visibility.

## 10. Skill Discovery

Skill metadata is matched first with bounded descriptions/triggers and deterministic
ordering. Full skill bodies load only after metadata selection. Existing skill trust
and scope owners remain authoritative.

## 11. Memory Integration

Memory is included only when task/workspace relevance checks pass. Historical
memory is represented as bounded `untrusted_memory` content and never as system or
developer authority. Stale generation memory is filtered by the same generation
boundary as other candidates.

## 12. Conversation Compaction

The model sees the most recent configured exact turns (default 12). Older transcript
rows remain in the append-only session store but are not replayed as an ever-growing
prompt. Deterministic `TaskStateSummary` retains goal, constraints, plan progress,
decisions, hypotheses, blockers, diagnostics, changed files, verification state,
and event sequence. A summary is emitted as bounded user-level untrusted model
observation; compression cannot elevate it to authority.

## 13. Scoped Project Instructions

`InstructionResolver` resolves supported `KHAOS.md` and `AGENTS.md` files from the
nearest project root through the target directory. Sibling package instructions
are excluded. Files are no-follow/size-bounded at 128 KiB and scoped resolution is
cached with a maximum of 128 entries. Cache keys include project, target, and each
instruction content digest.

## 14. Generation / Freshness

Workspace-bound items require generation. M8.1's normal generation format,
`workspace_epoch:manifest_digest`, is carried into every repository/verification/
edit item and into cache keys. An edit event invalidates old source and diagnostic
items; the next outer AgentLoop turn requests a new typed M8.1 bundle. The narrow
post-edit bare-epoch form is rebound only when it is waiting for that exact fresh
full generation; an old full generation is never accepted by epoch prefix alone.

Measured stale case:

```text
generation 40 source -> generation 41
old source selected at 41: false
new source selected at 41: true
result: partial=true, stale_retries=1
```

## 15. Cache / Persistence

`ContextCacheKey` binds workspace, task, generation, plan revision, step,
requirements digest, candidate digest, verification state, scope, principal, and
project. The LRU is bounded to 128 entries / 8 MiB. Working-set events invalidate
the affected task/workspace/scope; generation and principal/project checks prevent
cross-scope reuse.

Task metadata persistence stores bounded `TaskWorkingSet` state and references.
Restart restoration validates schema/digest and drops stale source, diagnostic, and
verification evidence while retaining task-level control facts.

## 16. Concurrency

Working-set updates and builds use task/workspace/scope locks with copy-on-write
events. There is no global asyncio serialization lock. A state race produces an
explicit partial/stale result and is not cached; it is never presented as a fresh
complete snapshot.

## 17. Security / Prompt Injection

Repository, tool, memory, verification, and model-derived content is framed with
explicit untrusted markers. Project instructions are the only project-trust input;
they do not alter Permission or Approval. Context metadata is derived from typed
engine items. Rebalance accepts typed classification only from an engine-emitted
`ContextMessage` or a process-local engine marker, so a provider/user `Message`
cannot forge L0/system trust by copying `context_*` metadata.

No M8.4 code bypasses Router, Permission, Approval, Workspace, Network, Credential,
EditTransaction, Verification, or Completion ownership. Evaluation traces retain
numeric metrics/digests, not prompt text or full tool output.

## 18. Metrics

`ContextMetricsSnapshot` and `CodingMetrics` expose context builds, input tokens and
bytes, L0/L1/L2/L3 distribution, selected/evicted/compressed items, cache
hit/miss, compaction, stale retries, stable prefix, schema cost, deferred
discovery, tool output cost/truncation, memory items, repository items, and
diagnostics. Missing provider/cache evidence remains `null`; it is not inferred as
a hit. M8.0 aggregate aliases are also emitted as `memory_items_selected`,
`repo_items_selected`, `diagnostics_selected`, and `compaction_count`.

## 19. Performance

The hot path has bounded candidate normalization, stable sorting, bounded region
merge, bounded serialization, and LRU cache reuse. Rebalances use recent exact
messages plus working-set state rather than replaying old transcript content.
Repository retrieval remains delegated to M8.1, so Context Engine does not add a
full-repository scan fallback.

## 23. Legacy Context Paths Removed

Normal factory-created runtimes no longer use the old unbounded context builder,
old direct repository message projection, legacy compressor, or direct raw tool
output path. The explicit `_build_legacy_context()` adapter remains only for
directly constructed compatibility/test loops where no Context Engine is supplied;
it is not a second normal production owner.
