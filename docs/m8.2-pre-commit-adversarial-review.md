## Invariants reviewed

- All operation preconditions, expected existence, content digests and workspace generation are checked before the first publish.
- A workspace storage lock serializes preview and mutation reads for the same workspace while allowing different workspaces to proceed independently. Generation CAS leaves one same-generation winner at `N+1`; the stale loser performs zero writes.
- Each file publish is atomic. The logical transaction records every published effect and rolls back in reverse order on a later failure. Final live state is re-snapshotted and validated before success is returned.
- Create, update, delete and rename use identity-bound recovery. Rename uses native no-replace where available and fails closed when the platform cannot prove the required operation. A third-party inode/content replacement is never overwritten by rollback; it enters quarantine/recovery-required.
- Storage quota/finalization is part of the commit boundary. A post-publish finalization failure attempts rollback and marks the workspace quarantined when success cannot be proven.
- Cancellation and timeout are settled through the storage authority before the mutation fence is released. Preview is read-only, lock-aware and rejects generation drift after lock acquisition.
- Transaction activity and task/memory telemetry retain bounded IDs, generations, digests, paths and operation metadata but redact source text, replacement text, intent text and preview diff. Model-facing preview output remains available only in the immediate tool result.
- Repository invalidation emits exact typed events for safe transaction operations and falls back conservatively when event derivation is not provable.
- Legacy Coding write, patch, multi-edit, delete, copy and move adapters use publish callbacks, identity/content verification and rollback/quarantine. A no-op multi-edit does not advance generation.

## Fault-injection matrix

The transaction tests cover failure before publish, after publish, after the second publish and during final verification/journal persistence. In particular:

- `test_preconditions_are_checked_for_every_file_before_publish` proves that a later precondition failure causes no initial publish.
- `test_failure_after_second_publish_rolls_back_before_third_operation` proves A/B effects are restored before C can be reported as successful.
- `test_post_publish_failure_is_recorded_for_rollback` proves the callback records an effect even when the lower layer raises after publish.
- `test_post_publish_external_content_drift_quarantines_without_rollback` proves unknown ownership is quarantined rather than destroying third-party content.
- `test_final_live_drift_is_not_reported_as_success` rejects a replacement/change in the final verification window.
- `test_finalize_failure_rolls_back_published_effect_and_quarantines` proves storage finalization is inside the commit boundary.
- Legacy adapter tests cover post-publish write/patch/multi/delete/copy/move failures and verify rollback or quarantine.
