# M8.8 Browser / App / Computer-Use Coding Closure Report

This is the implementation and verification record for M8.8. A local
`PASS` means the named contract and local test evidence passed; it does not
promote a macOS deterministic adapter or fake page into real Linux browser
kernel or real-provider capability evidence.

## 1. Executive Summary

M8.8 adds a typed Browser Coding facade for local app launch, bounded browser
observation, semantic actions, screenshots, credentials, lifecycle recovery,
and M8.3 browser verification. It reuses the existing execution, Browser
Manager, NetworkGuard, approval, credential, workspace, supervision, context,
and completion authorities. No unrestricted subprocess, browser, or network
path was added.

## 2. M8.7 Baseline

The implementation continues the existing M8.7 extension, hook, skill, MCP,
supervision, subagent, and workspace-generation contracts. Browser inputs are
an additional low-trust evidence source; they do not become extension or
completion authority.

## 3. Browser/App Threat Model

Page text, DOM, ARIA/accessibility data, titles, URLs, console messages,
network summaries, tooltips, modal text, screenshots, downloads, and app output
are untrusted. They may contain prompt injection and cannot approve, verify,
complete, read secrets, change policy, or widen an authority scope.

## 4. Existing Browser Security Reuse

`BrowserCodingService` is a thin composition over the existing
`BrowserManager`, `BrowserEgressProxy`, `NetworkGuard`, `ExecutionService`,
`ApprovalBroker`, `CredentialBroker`, and browser TCB lifecycle. It does not
launch Playwright or Chromium itself and has no duplicate network policy.

## 5. Authority Ownership Map

ExecutionService owns app process launch and termination. BrowserManager owns
the browser context/page lifecycle. NetworkGuard owns target policy.
ApprovalBroker owns effect admission. CredentialBroker owns credential leases.
WorkspaceManager owns task workspace and generation. VerificationExecutor and
CompletionGate remain the verification and completion authorities.

## 6. BrowserSessionBinding

`BrowserSessionBinding` is immutable and binds principal, project, task,
workspace, workspace generation, repository generation, runtime, browser
runtime/context, app instance digest, exact origin, policy digest, state, and
binding digest. Old identity is never reused after restart or recovery.

## 7. AppInstance Contract

`AppInstance` records the trusted profile digest, task/workspace identity,
execution owner, exact `127.0.0.1:port`, origin, lifecycle state, health, and
instance digest. The record is not page evidence and cannot authorize a
browser action.

## 8. App Launch Profiles

`AppLaunchProfile` requires a trusted explicit provenance, an absolute
executable, exactly one `{port}` placeholder, workspace-relative cwd,
bounded readiness path/statuses, loopback binding, and a bounded environment.
Shell launchers, inline evaluation, `PORT` overrides, credential-shaped keys,
and shell-control syntax are rejected.

## 9. Dev Server Lifecycle

The dev server is launched through `ExecutionService` as a task-owned managed
process. Readiness is bounded and probes the exact profile origin/path. The
managed execution environment preserves only explicitly allowed profile keys
while still overriding HOME/TMPDIR and maintaining the existing sandbox.

## 10. Port / Network Isolation

Port reservations and endpoint bindings are exact loopback host/port records.
Browser context creation receives an immutable endpoint snapshot, so a wider
legacy context cannot be reused for a narrower app scope. macOS allows only
the requested inbound loopback ports; Linux bubblewrap fails closed when a
local listener cannot be safely represented without widening the namespace.

## 11. Browser Action Model

Actions are typed semantic operations: navigate, click, type, select, key
press, scroll, wait, read, screenshot, upload, and explicitly blocked
download/new-page operations. Each action has a bounded selector/value digest,
effect class, sequence, binding, and action digest.

## 12. Browser Action Admission

Admission checks the exact session/app/task/workspace/principal/generation and
stale preconditions. UI inputs and external effects use the existing approval
broker; missing, mismatched, or stale approval and policy digests are denied.
Action values are never returned as durable model evidence.

## 13. Origin Policy

Only plain HTTP(S) loopback origins with an exact port are accepted. The
canonical form is `http://127.0.0.1:<port>` (or the equivalent HTTPS form).
Paths, queries, fragments, userinfo, non-loopback hosts, invalid ports, and
origin escapes are rejected.

## 14. Redirect / DNS Security

The bound page URL is checked after navigation and readiness, and every
observed/action target is checked against the exact allowed origin. `localhost`
is canonicalized to `127.0.0.1`; DNS-controlled or redirect-controlled
external targets are not accepted as task app origins.

## 15. Credential Injection

Credential actions require a named preissued `CredentialLease` and the
existing `CredentialBroker`. The lease binds the exact principal, project,
task, workspace generation, session, app, origin, selector, credential name,
policy, and purpose. The value exists only in memory, is typed rather than
model-supplied, and is redacted from observations; screenshots are disabled
after credential injection.

## 16. Browser Observation Model

`BrowserObservation` is immutable, bounded, and forcibly labeled
`untrusted-observation`. Title, URL, body summary, console, network, and
artifact references are capped and redacted. Observation payloads contain
digests/metadata rather than raw durable page content.

## 17. DOM / Accessibility Bounds

The facade exposes bounded semantic page observations only. It does not expose
full HTML, raw DOM objects, arbitrary model JavaScript, `evaluate`, XPath,
coordinate selectors, or native page execution. Accessibility text remains
untrusted browser observation.

## 18. Console Evidence

Console entries are collected only as bounded descriptive strings, redacted,
and included in observation/evidence digests when applicable. Console content
cannot become an instruction, approval, policy update, or completion claim.

## 19. Network Evidence

Network entries are bounded and descriptive. Target authorization remains the
NetworkGuard/BrowserEgressProxy decision, not page-reported network text.
Network output does not carry credentials or create a new lease.

## 20. Screenshot / Artifact Handling

Screenshots are held by a bounded, quarantined `BrowserArtifactStore` and are
represented outside the service by metadata-only references and SHA-256
digests. Artifact count/size totals are capped and close clears owned bytes;
downloads are never opened or executed by this store.

## 21. Browser Verification Checks

`BrowserVerificationSpec` contains bounded typed checks and assertions bound to
the app profile, action sequence, workspace/repository generation, and exact
session/app identity. Verification results are explicit pass/fail/stale/
environment-blocked/unknown states.

## 22. M8.3 Integration

Frontend/UI impact selects a browser check in the ordinary M8.3 autonomous
verification plan. `VerificationExecutor` invokes the composed browser
service and maps its typed result into the existing M8.3 evidence/status
model. M8.3 remains the verification authority.

## 23. Evidence Generation Binding

Browser evidence binds plan/check/workspace/repository generation,
principal/task/session/app/action/observation digests, timing, and terminal
state. A planner, browser page, or metrics record cannot self-authorize
completion; CompletionGate remains final authority.

## 24. Repair / Reverification Loop

The deterministic M8.0 full-stack fixture observes the defect, creates a
structured diagnostic, applies a workspace edit, restarts the app under a new
identity/generation, and reruns M8.3 through `VerificationExecutor`. A stale
or unproven lifecycle result is negative evidence, not green repair evidence.

## 25. AgentLoop Integration

Browser tools are registered only in Coding mode with an active task
workspace. AgentLoop tags browser tool observations as browser-sourced L3
untrusted context. The tool handlers inject trusted identity/workspace scope;
model messages cannot supply authority fields or credential values.

## 26. M8.4 Context Integration

The context engine includes `Source.BROWSER` and the
`UNTRUSTED_BROWSER_CONTENT`/`BROWSER_OBSERVATION` trust labels. Browser data is
bounded, provenance-tagged, and retains its low trust through compression and
child context projection.

## 27. M8.5 Subagent Semantics

Subagents receive their own scoped task/workspace/principal context through
the existing composition. Parent browser sessions, approvals, credentials,
evidence, and live page objects are not inherited. Mutating children cannot
share a parent-owned dev server as an implicit authority.

## 28. M8.6 Supervision / Pause / Cancel / Rewind

Browser lifecycle events are descriptive inputs to the existing supervision
service. Pause/cancel paths attempt shielded terminal cleanup and retain
quarantine on uncertainty. Rewind restores repository/workspace state only;
it does not rewind external app state or claim that an external effect was
undone.

## 29. M8.7 Extension Interaction

Extension, MCP, hook, and skill outputs remain untrusted metadata and cannot
replace built-in browser authority. The browser facade does not grant an
extension a hidden page handle, unrestricted JS, credential lease, or policy
mutation path.

## 30. Upload / Download Boundary

Upload paths reuse the existing secure workspace-relative reader and reject
traversal and protected metadata. Download/new-page support is explicitly
blocked in this closure until a bounded quarantine adapter and authoritative
effect model are composed; there is no implicit download execution.

## 31. Restart / Recovery

Migration v32 persists metadata-only app/session state and lifecycle events.
`recover_persisted_resources()` is explicit, never reuses an old identity, and
marks stale resources or cleanup uncertainty as `stale`/`quarantined`.
`restart_app()` closes the prior session/app and reopens under a fresh identity
and permitted repository generation.

## 32. Quarantine

Process, browser context, artifact, endpoint, and journal cleanup are separate
ownership edges. If terminal proof is missing, the service retains ownership
and refuses false `CLOSED`/success. Failed endpoint unbinds remain quarantined
until disappearance is proven.

## 33. External Effect Truth

Effect results distinguish not-applied, applied, and unknown. A timeout,
cancellation, lost response, or network break after a possible form submit
cannot be inferred as success or failure; retry requires an explicit safe
idempotency/effect-state contract and approval.

## 34. Security Adversarial Matrix

Covered locally: prompt-injection observations cannot approve/verify/complete;
semantic/code/coordinate selectors are rejected; profile/origin escapes are
rejected; identity/generation/approval mismatches are rejected; credential
values are excluded from model/durable payloads; artifact and lifecycle bounds
are enforced; no host-browser fallback is accepted. No blocker, high, medium,
or low finding remains in this implementation review. Three informational
environment boundaries remain documented in section 45.

## 35. Long-Session Resource Bounds

Sessions, apps, event items, selectors, observations, artifacts, artifact
bytes, action duration, readiness, navigation, and output fields have explicit
caps. Metrics counters are bounded and non-authoritative. Close paths clear
artifact bytes and release process/context/endpoint ownership with proof.

## 36. Evaluation Metrics

`BrowserMetrics` records sessions, actions, observations, checks, failures,
launches/restarts, context/evidence bytes, screenshots, denials, approvals,
time-to-first-observation, time-to-green, and repairs. Metrics are black-box
descriptors only; zero prompt-injection/repair counters do not imply a real
provider benchmark was run.

## 37. M8.0 Browser Scenarios

The builtin manifest now has 15 scenarios, including the deterministic
`browser-frontend-bug`, `browser-fullstack-bug`, and
`browser-validated-feature` fixtures. The full-stack deterministic E2E covers
reproduce, structured diagnostic, edit, app restart, new-generation binding,
and M8.3 `PASSED` evidence. Hidden oracle material remains outside the agent
workspace.

## 38. Python Regression

`make test-python` built the release native execution launcher and ran 5,527
tests. Result: `5474 passed, 50 skipped`; three initial failures were stale
generated inventories caused by the new reachable/spawned modules. After the
repository generators refreshed those derived documents, the exact inventory
checks passed (`7 passed`). Focused results: M8.8 `12 passed`; M8.8+M8.3
`44 passed`; browser tools `90 passed`; execution/browser security `60
passed`; context `17 passed`; evaluation `113 passed`.

## 39. Go Regression

`make test-go` passed all configured Go packages: gateway, API, auth, metrics,
platform, rate, and websocket packages. The websocket subpackage had no test
files and was reported as such by `go test`.

## 40. Rust Regression

`make test-rust` passed the Rust TCB suite: 18 library tests and 5
`khaos-exec-launcher` tests, with all other binary/doc-test targets terminal
success and no failures.

## 41. Browser Security Regression

The full Python run passed the existing browser egress, context, lifecycle,
TCB-path, credential, network-guard, cleanup, and browser helper suites; Linux
kernel-dependent tests remained explicit skips on this macOS host. The focused
execution/browser-security set passed `60` tests. No local macOS result is
claimed as Linux netns/nft/cgroup/Chromium proof.

## 42. Static / Reachability

Ruff, `git diff --check`, selected Python compilation, migration source
integrity, production reachability, security inventory, and privileged-spawn
inventory checks are green. The generated reachability/security inventories
were refreshed with their repository-owned generators after adding the M8.8
production path.

## 43. CI Evidence

Exact-SHA CI is not yet available for the final implementation because the
changes have not been committed and pushed. Required product-integrity,
security-closure, browser/security, Go, Rust, and other required workflows
must be terminal success for the final pushed SHA and attempt. Earlier-SHA or
non-terminal results cannot close this report.

## 44. Platform Applicability

Local evidence is macOS with the existing sandbox/native development adapter
and deterministic fake browser manager. Linux bubblewrap/network-namespace,
nft, cgroup, and real Chromium evidence is CI/environment-dependent. Windows
native helper evidence remains governed by the existing Windows-specific
gates.

## 45. Known Limitations

The following are intentionally not claimed: real Linux browser-kernel E2E;
real provider browser benchmark; popup/new-tab and cross-origin iframe
adapters; full download quarantine; arbitrary native desktop mouse/keyboard,
Electron, or other OS GUI control. These are documented boundaries rather
than unsafe fallbacks.

browser tools, registry, network guard, persistence migration v32, M8.0
