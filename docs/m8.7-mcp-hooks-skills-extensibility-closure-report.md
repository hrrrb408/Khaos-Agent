# 1. Executive Summary

M8.7 adds one controlled extension plane for configured MCP servers, Hooks, and
declarative Skills.  Capabilities remain descriptive until the existing
admission and execution owners independently authorize an invocation.

# 2. Baseline

Baseline branch: `codex/m8-coding-evaluation` at `4efa9d34ca998154ec738b15c4161bf5abae6b68` (`4efa9d3`, M8.6 exact-SHA closure).

# 3. Extension Threat Model

Threats include repository-controlled extension injection, prompt injection,
tool-name collisions, under-declared effects, SSRF/DNS rebinding, fake PATH or
package launchers, credential leakage, server crash/restart loops, Hook
recursion/storms, Skill traversal/symlink escape, replay, owner drift, and
provider-supplied authority-shaped claims.

# 4. Extension Trust Classes

Descriptors preserve provenance (`BUILTIN`, trusted local config,
project-declared, and local-untrusted).  Provider output, resources, prompts,
Hook results, and Skill body text are lower-trust data.

# 5. Extension Descriptor

`ExtensionDescriptor` binds source, version, transport, artifact/config
identity, metadata, enabled state, and a canonical descriptor digest.  Sensitive
and authority-shaped fields are rejected or kept out of model context.

# 6. Provenance

Provenance is immutable descriptor data and is included in digests, registry
records, context labels, and audit-safe projections.  It is not a substitute
for approval or execution authority.

# 7. Extension Registry

`ExtensionRegistry` is the sole discovery/validation/lifecycle registry.  It
does not register external capabilities in the built-in `ToolRegistry` and
protects built-in name collisions.

# 8. Capability Descriptor

Tools, resources, prompts, Hooks, and Skills use typed descriptors with
bounded schemas, names, metadata, effect declarations, and capability digests.

# 9. Capability Admission

`CapabilityAdmissionService` revalidates current registry state and binds owner,
task, project, workspace/generation, policy, approval, credential, network,
extension, capability, and request digests before issuing an invocation binding.

# 10. Tool Registry Integration

Built-in tool discovery remains authoritative for built-in tools.  External
tool schemas are exposed through Context Engine metadata only; execution still
uses the unified extension admission path and existing effect owners.

# 11. MCP Transport Architecture

`McpServerSession` owns handshake, discovery, validation, per-task budgets,
transport health, and cleanup.  Stdio process ownership and remote network
authority are injected from existing owner seams; this module contains no raw
process spawn.

# 12. Local MCP Lifecycle

Stdio requires an absolute regular executable, explicit artifact digest,
bounded argv, no shell/package launcher, model-writable-root exclusion, and
scrubbed environment.  Lifecycle transitions are explicit and availability is
not implied by discovery.

# 13. Remote MCP Lifecycle

HTTP endpoints use existing network authorization, no implicit redirects,
approved DNS target pinning, private-address rejection, and degradation on
transport failure.  An uncertain close retains quarantine rather than claiming
`CLOSED`.

# 14. MCP Tool Discovery

Initialize and paginated tool/resource/prompt discovery enforce page, count,
cursor, message, and schema bounds.  Dynamic list changes degrade the session
and require a fresh validation/lifecycle path.

# 15. MCP Resource Handling

Resource URIs reject dangerous schemes, credentials, control characters, and
traversal.  Read results are immutable bounded extension-resource context and
cannot become policy or system instructions.

# 16. MCP Prompt Handling

Prompt arguments pass the declared schema and normal admission path.  Prompt
results are labeled `EXTENSION_INSTRUCTION` and remain low-trust context.

# 17. MCP Schema Limits

The closed JSON-schema subset limits depth, nodes, properties, enums, schema
bytes, and argument bytes.  Unknown or malformed schemas fail closed.

# 18. MCP Output Limits

Canonical JSON byte bounds apply to messages, tool results, resource/prompt
data, task totals, and context projections.  Authority-shaped result fields
are stripped and recorded only as ignored diagnostics.

# 19. MCP Credentials

Credential names are binding inputs only.  No credential value is placed in
MCP output, model context, Skill text, Hook payloads, or durable projections.

# 20. MCP Network Security

HTTP endpoints reject localhost/private/special targets by default.  Network
authority must return a `ValidatedTarget`; malformed authority results fail
closed.  Cross-host redirects and HTTPS-to-HTTP downgrades are denied.

# 21. MCP Cancellation/Recovery

Timeout and cancellation paths degrade the transport and shield cleanup.
Restart count, notification rate, in-flight calls, total calls/bytes, and wall
time are bounded; cleanup uncertainty enters quarantine.

# 22. Hook Architecture

Hook descriptors and immutable event projections support observe, advise, and
trusted blocking modes.  Hooks cannot mutate canonical events or become a
control-plane writer.

# 23. Hook Recursion Control

Context-local causal depth is limited to one nested dispatch; reentrant Hook
dispatch and event storms are bounded and reported as non-authoritative Hook
failures.

# 24. Hook Budgets

Hook count, tool-request count, event/result bytes, timeout, deterministic order,
and failure isolation are bounded.  Hook tool requests re-enter normal
capability admission and never self-approve.

# 25. Skill Package Model

Skill packages bind manifest, body digest, examples, provenance, required and
optional tools, applicability selectors, and package digest.  They are data,
not imported Python modules.

# 26. Skill Instruction Trust

Skill instructions are `UNTRUSTED_EXTENSION_INSTRUCTION` and are injected only
through Context Engine extension projections.  Authority-shaped metadata and
remote/executable instruction fragments are rejected.

# 27. Skill Selection / Context Integration

Selection produces active, partially available, denied, or stale activation
projections.  Required missing tools never create a capability.  Context Engine
limits extension items/bytes and keeps extension diagnostics/resources separate
from system authority.

# 28. Child/Subagent Extension Scope

Child runtime composition does not inherit the parent registry or credentials;
the current production path exposes an empty child extension subset, which is
conservative and cannot escalate.  Explicit subset assignment remains a
future owner-scoped extension point.

# 29. Approval / Effect Binding

Declared effects are structural and can only be narrowed by policy.  Approval,
policy, owner, workspace, network, credential, descriptor, capability, and
request drift invalidate the binding; replay and cross-project/task attempts
fail closed.

# 30. Supervision Integration

Extension lifecycle, MCP, Hook, admission, and Skill events use an explicit
extension event allowlist and namespaced payload fields.  Provider-controlled
`status`, verification, approval, and completion keys cannot overwrite the
canonical task timeline.

# 31. Durable State / Recovery

Migration v31 adds owner-scoped descriptor/capability/runtime/invocation,
Hook-registration, and Skill-activation projections.  Identity/audit rows are
append-only; runtime process/session identity is immutable per instance id.

# 32. Adversarial Security Matrix

collision protection, fake PATH/package launchers, executable drift, SSRF and

drift, owner/replay/policy/workspace drift, supervision spoof, quarantine, and
runtime cleanup uncertainty.
