## 3. Artifact-Bound MergePlan

`MergePlan` now persists parent task/workspace/principal/project identity,
generation/HEAD, deterministic candidate order, conflict analysis, and complete
`candidate_bindings`. Its digest includes all of those values and the expected
publication semantics. The merge path rejects a plan whose parent trust domain,
candidate set, or binding tuple differs; it never silently replans.

## 4. Candidate Binding

`MergeCandidateBinding` is constructed only from a typed,
`SubagentResult.validate_against()`-validated `SubagentAssignment` and result. It
binds assignment digest, result digest, Child workspace/final commit, change
digest, artifact path/SHA-256/length, changed paths, and verification evidence
digest. The readable assignment ID is not authority by itself.

## 5. Merge Determinism

Candidates are ordered by `(assignment.priority, assignment_id)`. The merge
identity is derived from the complete binding payload, parent snapshot, order,
and conflicts. The regression suite builds ten plans with alternating input
completion order and asserts identical `merge_id`, `plan_digest`, order, and
binding result digests.

## 6. Integration Verification

All exact candidate artifacts are applied to a private Integration Worktree.
M8.3 typed verification is required on the production path; boolean/mapping
verifiers are available only through an explicit test-double flag. Failed,
timed-out, or infrastructure-error integration verification returns
`VERIFICATION_FAILED` without changing Parent HEAD, generation, or files.

## 7. Verified Integration Artifact

After a passing integration verification, WorkspaceManager copies and rechecks
the ChangeSet artifact into an independent manager-owned storage identity. The
`VerifiedIntegrationArtifact` binds merge/plan digest, base commit, resulting
Git tree, artifact SHA-256/length, changed paths, verification evidence, and
storage identity. Parent publication reads this frozen artifact rather than a
mutable Integration Worktree.

## 8. Parent CAS Publication

Publication requires the Parent to remain clean and to match the planned
generation and HEAD. It uses `WorkspaceManager.commit_current_changeset()` with
the expected HEAD/generation fence. A Parent change after the artifact is frozen
is rejected as `REJECTED_STALE`; no user workspace reset or `git clean` is used.

## 9. Publication Integrity Attestation

`PublicationAttestation` is a new evidence object, not a rebind of old evidence.
It records both commits, generations, workspace identities, source verification
evidence, plan/verification digests, and changed paths. It is constructed only
after a trusted current Parent observation proves exact
`integration_commit^{tree} == parent_commit^{tree}`.

## 10. Current-Generation Verification Evidence

The post-publication M8.3 call is an Option A consistency audit. Code correctness
comes from the pre-publication typed integration proof; the Parent stage checks
the current generation and publication consistency. Audit failure, attestation
failure, or Repo Intelligence refresh failure cannot return plain `PUBLISHED`.
The resulting state is `PUBLISHED_UNVERIFIED` or `PUBLISHED_QUARANTINED`, and
CompletionGate remains the only completion authority.

## 11. Child Cleanup Barrier

After candidate artifacts have been applied and the verified integration artifact
has been frozen, MergeCoordinator invokes the existing ChildWorkspaceService
lifecycle owner. Every successful Child must return explicit `CLEANED` plus an
accepted terminal transition before Parent publication. A failure retains the
resource and returns pre-publication `QUARANTINED`.

## 12. Integration Cleanup Barrier

The frozen artifact is independent of the Integration Worktree. MergeCoordinator
drains Integration cleanup before the Parent publish fence. Cleanup failure or
cancellation before that fence leaves Parent unchanged and produces
`QUARANTINED`/`CANCELLED` according to the observed effect; retained ownership is
not reported as closed.

## 13. Cancellation Semantics

Cleanup and publication effects are drained through shielded owned tasks. A
cancellation before the publication barrier leaves Parent unpublished. A
cancellation during a committed Parent effect is reported with the observed
published head and `PUBLISHED_UNVERIFIED`; it is never misreported as plain
`CANCELLED`.

## 14. Restart / Unknown Effect Recovery

v29 JSON and append-only events carry plan, binding, artifact, barrier, publication,
attestation, and cleanup digests without changing historical migrations. Active
interrupted records reconcile to `UNKNOWN`; already quarantined records remain
`QUARANTINED` and require recovery. A verified artifact can be re-admitted only
through WorkspaceManager exact storage identity, SHA-256, and length checks; no
restart path infers success from an interrupted effect.

## 15. Replay Resistance

The plan/generation/HEAD and trust-domain checks reject double publication, old
generation replay, and cross-workspace/project replay. A second attempt using a
published plan cannot advance Parent a second time. Candidate, artifact, and
verification evidence substitution changes the binding tuple and is rejected.

## 16. CompletionGate Integration

M8.5 does not create a second completion authority. Child evidence is never
directly promoted to Parent evidence. Only the exact publication attestation and
current-generation observations are exposed as merge evidence; existing
CompletionGate decides whether the broader task may complete.

## 17. Security Adversarial Matrix

Covered cases include result digest, artifact SHA/length/path, Child HEAD, change
digest, changed-path, verification-evidence, and assignment substitution;
integration failure/timeout/infrastructure error; artifact tamper; Parent CAS
drift; post-publish tree drift; Child/Integration cleanup failure; cleanup and
publication cancellation; durable quarantine recovery; double publish; old plan
replay; and cross workspace/project replay.

## 20. Known Limitations

- No real external model/provider capability test is introduced by this
  remediation: `REAL CAPABILITY DELTA = UNKNOWN`.

  operation; it does not guess whether an interrupted Git effect applied.
